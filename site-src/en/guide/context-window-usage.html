Every Claude Code session carries a conversation: your prompts, the files it read, tool output, and its own replies. All of that has to fit in the model's context window. When it gets close to full, Claude Code summarizes the conversation so far and carries on from the summary. That is auto-compact. It keeps the session alive, but details from earlier in the conversation get squeezed into a few paragraphs, so it pays to know when it is coming.

Context window vs. auto-compact threshold

The number that matters is not the window size itself. Claude Code compacts before the window is full, because it needs room to write the summary and a little slack on top. The overlay works out the threshold the same way:

threshold = min(window, autoCompactWindow) − min(max output tokens, 20,000) − 13,000

For a model with a 200,000-token window and 32,000 output tokens, that is 200,000 − 20,000 − 13,000 = 167,000 tokens. A session sitting at 140k tokens looks like 70% of the window, but it is already 84% of the way to compaction. That gap is why the overlay shows its percentage against the threshold, not against the raw window: 100% means "compacts now".

Models with a 1M-token context (the ones marked [1m]) get the same treatment with a much larger window, which is why they can run for hours before compacting.

Where the numbers come from

The model's window and output limit come from the model catalog that Claude Code caches under ~/.claude/cache/model-catalog/. If you have lowered the compaction point yourself, the overlay picks that up too: the CLAUDE_CODE_AUTO_COMPACT_WINDOW environment variable wins, and otherwise it reads autoCompactWindow from ~/.claude/settings.json. The token count for each session comes from the last usage entry in its transcript (~/.claude/projects/<project>/<session>.jsonl), so the number updates every time the model replies.

Reading the colors

Each session row shows a percentage such as 46%. The color follows the same scale as the Claude desktop app's usage display:

  • Blue under 75%: plenty of room.
  • Yellow from 75% to 90%: start thinking about a good place to stop.
  • Red at 90% and above: compaction is close.

When a session crosses 90%, the overlay also plays a chime and reads out a short line such as "my-repo context 91 percent", so you hear about it even when the session is in a window you are not looking at. Alerts stay silent while the screen is locked or off.

Compacting on your own terms

Automatic compaction happens whenever the threshold is hit, which may be in the middle of a refactor. You get a better summary if you compact at a natural break instead: after a commit, after tests pass, or before you switch to a different part of the codebase. In Claude Code you can run /compact yourself at any time, and add a hint about what to keep, for example /compact keep the list of files we changed. The /context command shows what is taking up space in the current session.

If you install the optional session-hud mod that ships with the overlay, each session row gets a ⇣ compact button that runs /compact in that session, and Claude Code's prompt gets a one-line HUD with the same context bar.

Habits that keep context usage down

Large tool outputs are the usual culprit. Reading whole generated files, dumping long logs, or running a test suite with verbose output can add tens of thousands of tokens in one go. Ask for the relevant part (a function, the failing test, the last 50 lines) instead. Starting a fresh session for an unrelated task is cheaper than compacting an old one, and subagents keep their exploration out of the main conversation, since only their conclusion comes back.

With several sessions open, the hard part is noticing which one is close to the limit. That is what the overlay is for: every session's percentage is in one always-on-top list, so a red number stands out before it turns into a surprise summary.
