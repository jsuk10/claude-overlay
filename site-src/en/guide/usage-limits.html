If you use Claude Code on a Claude subscription rather than an API key, your usage is metered in two windows at once: a 5-hour session limit and a weekly limit. Hitting either one pauses your work until it resets. Both are easy to lose track of when several sessions are running, because each session only shows its own conversation, while the limits belong to your whole account.

Two limits, one account

The 5-hour limit covers a rolling window that starts with your first message and resets five hours later. It is the one you bump into during an intense afternoon. The weekly limit is a larger budget that resets once a week; it is the one that catches up with you after several heavy days in a row.

What matters for Claude Code is that every session draws from the same pool. Three sessions running side by side spend the 5-hour budget roughly three times as fast as one. Sessions in the terminal and sessions in the Claude desktop app's Code tab count the same way. So "how much do I have left?" is an account-level question, and no single session window can answer it for you.

Where to see the numbers

The Claude desktop app records your plan usage locally about every five minutes, in a file called plan-usage-history.json inside its data folder (%APPDATA%\Claude on Windows, ~/Library/Application Support/Claude/ on macOS). The overlay reads the latest sample from that file and shows:

  • Weekly usage on the header line at the top of the overlay.
  • The 5-hour session limit on the bottom line, as a percentage with a colored bar.

Hover over either one for the exact figure. If the desktop app has not recorded anything yet, the bottom line says so ("shown once the Claude desktop app records usage") instead of showing a stale or made-up number. You only need the desktop app installed and signed in; it does not need to be in the foreground.

Reset times with the session-hud mod

The optional session-hud mod adds a second source. It reports the usage figures Claude Code receives with each reply, including when each limit resets. With the mod installed the bottom line reads like 5-hour session limit 62% used · reset 1h 40m, so you can decide whether to push on or take a break.

When both sources are available, the overlay takes the most recent reading for each limit separately. A reading older than the limit's own window is thrown away: a 5-hour figure from six hours ago says nothing about now, because the window has reset since.

On macOS: the menu bar and widgets

On a Mac the same numbers show up outside the overlay window too. The menu bar item next to the ✻ icon adds the 5-hour percentage once it passes 75%, so it stays quiet until it matters. Its menu lists both weekly and 5-hour usage. The small widget shows the 5-hour limit next to the session counts, and the large and extra-large widgets draw bars for both limits.

Stretching your limits

Usage is driven by how much the model reads and writes, so the habits that keep context small also save your limits: ask for the part of a file or log you need, start fresh sessions for unrelated tasks instead of dragging a huge conversation along, and stop sessions you are no longer watching. A session that keeps running background work while you are away still spends from the same pool.

Keeping the 5-hour number in the corner of your screen turns the limit from a surprise into a plan. When it is at 80% with two hours to go before the reset, you know to finish the current task rather than start a big new one.
