Claude Code 세션에는 대화가 쌓입니다. 내가 보낸 프롬프트, 모델이 읽은 파일, 도구 실행 결과, 모델의 답이 전부 들어갑니다. 이 모두가 모델의 컨텍스트 창 안에 들어가야 하고, 창이 거의 차면 Claude Code는 그때까지의 대화를 요약한 뒤 요약본을 이어받아 계속 일합니다. 이게 자동 압축(auto-compact)입니다. 세션은 살아남지만 앞쪽 대화의 세부 내용은 몇 문단으로 줄어듭니다. 그래서 언제 압축이 올지 알고 있는 편이 낫습니다.

컨텍스트 창과 압축 기준은 다르다

중요한 숫자는 창 크기 자체가 아닙니다. Claude Code는 창이 꽉 차기 전에 압축합니다. 요약을 써 넣을 자리와 약간의 여유가 필요하기 때문입니다. 오버레이도 같은 방식으로 기준을 계산합니다.

압축 기준 = min(창 크기, autoCompactWindow) − min(최대 출력 토큰, 20,000) − 13,000

창이 20만 토큰이고 출력이 3만2천 토큰인 모델이면 200,000 − 20,000 − 13,000 = 167,000 토큰입니다. 14만 토큰을 쓴 세션은 창 기준으로는 70%처럼 보이지만, 압축까지는 이미 84%를 온 셈입니다. 오버레이가 창이 아니라 압축 기준에 맞춰 %를 보여 주는 이유가 이 차이입니다. 100%는 "지금 압축된다"는 뜻입니다.

100만 토큰 컨텍스트 모델([1m]이 붙은 모델)도 계산 방식은 같고 창만 훨씬 큽니다. 그래서 몇 시간을 돌려도 압축되지 않는 경우가 많습니다.

숫자는 어디서 오나

모델의 창 크기와 출력 한도는 Claude Code가 ~/.claude/cache/model-catalog/에 받아 두는 모델 목록에서 읽습니다. 압축 시점을 직접 낮춰 두었다면 그것도 반영합니다. 환경 변수 CLAUDE_CODE_AUTO_COMPACT_WINDOW가 있으면 그 값을 쓰고, 없으면 ~/.claude/settings.json의 autoCompactWindow를 읽습니다. 세션마다 쓴 토큰 수는 대화 기록(~/.claude/projects/<프로젝트>/<세션>.jsonl)의 마지막 사용량 항목에서 가져오므로, 모델이 답할 때마다 숫자가 바뀝니다.

색깔 읽는 법

세션 줄마다 46% 같은 숫자가 붙습니다. 색은 Claude 데스크톱 앱의 사용량 표시와 같은 기준을 따릅니다.

  • 파랑(75% 미만): 여유가 있습니다.
  • 노랑(75~90%): 끊어 갈 지점을 슬슬 찾을 때입니다.
  • 빨강(90% 이상): 곧 압축됩니다.

세션이 90%를 넘으면 짧은 소리와 함께 "my-repo 컨텍스트 91퍼센트"처럼 음성으로도 알려 줍니다. 그 세션 창을 보고 있지 않아도 놓치지 않게 하려는 것입니다. 화면이 잠겨 있거나 꺼져 있을 때는 울리지 않습니다.

압축은 내가 고른 때에

자동 압축은 기준에 닿는 순간 일어나니, 리팩터링 한가운데일 수도 있습니다. 커밋한 직후, 테스트가 통과한 직후, 다른 부분으로 넘어가기 직전처럼 자연스럽게 끊기는 지점에서 직접 압축하면 요약 품질이 더 좋습니다. Claude Code에서는 언제든 /compact를 직접 실행할 수 있고, /compact 바꾼 파일 목록은 남겨 줘처럼 무엇을 남길지 덧붙일 수도 있습니다. /context 명령은 지금 세션에서 무엇이 자리를 차지하고 있는지 보여 줍니다.

오버레이에 함께 들어 있는 session-hud Mod를 설치하면 세션 줄마다 ⇣ 압축 버튼이 생겨 그 세션에서 /compact를 실행하고, Claude Code 프롬프트 위에도 같은 컨텍스트 막대가 한 줄로 뜹니다.

컨텍스트를 아끼는 습관

범인은 대개 큰 도구 출력입니다. 자동 생성된 파일을 통째로 읽히거나, 긴 로그를 쏟아내거나, 테스트를 자세한 출력으로 돌리면 한 번에 수만 토큰이 늘어납니다. 필요한 부분(함수 하나, 실패한 테스트, 마지막 50줄)만 달라고 하세요. 관련 없는 작업은 오래된 세션을 압축하는 것보다 새 세션을 여는 편이 싸고, 서브에이전트를 쓰면 탐색 과정은 본 대화에 남지 않고 결론만 돌아옵니다.

세션이 여러 개일 때 어려운 건 어느 세션이 한계에 가까운지 알아채는 일입니다. 오버레이가 하는 일이 바로 그것입니다. 모든 세션의 %가 항상 위에 뜬 목록 하나에 모여 있으니, 빨간 숫자가 갑작스러운 요약으로 바뀌기 전에 눈에 띕니다.
