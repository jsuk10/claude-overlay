Running several Claude Code sessions at once without losing track

Updated: October 20, 2026

Running two, three or five Claude Code sessions side by side is one of the best ways to get more done: one session refactors, another writes tests, a third investigates a bug. The catch is attention. Sessions stop to ask for permission, finish while you are looking elsewhere, or quietly fill their context. With a few terminal tabs and a desktop app window open, it is easy to find out half an hour later that a session has been waiting for a single "yes".

The three states that matter

The overlay sorts every live session into one of three states and shows them in a single always-on-top list:

  • Working: the model is busy. Nothing for you to do yet; the row shows how long it has been running.
  • Needs input: the session is waiting for you, either at a permission prompt or with a question. This is the state that costs the most time when you miss it.
  • Done, not yet seen: the session finished its turn and you have not looked at it since.

Sessions you have already seen drop out of the list so it stays short. Opening a session counts as seeing it, whether you click its row, focus its window in the desktop app, or mark it seen from the right-click menu. Sessions you want to keep in view no matter what can be starred: ★ favorites always stay in the list.

Alerts you can hear

A list only helps if you look at it. So the overlay also plays a short chime and speaks a line when something changes: "my-repo done" when a session finishes, "my-repo needs input" when it starts waiting, and a context warning when it crosses 90%. On Windows it uses the built-in text-to-speech voice; on macOS it uses say with a natural-sounding voice. You can turn sound and voice off separately from the tray menu, and alerts stay silent while the screen is locked, asleep or off, so you do not come back to a backlog of announcements.

One click to the right window

Click a session row and the overlay brings that session to the front. For CLI sessions it finds the terminal window running it. For sessions in the Claude desktop app's Code tab it opens that session in the app, and if the session is already showing in split view, it moves the cursor into that pane's prompt box without rearranging your layout. On macOS, sessions in Terminal or iTerm2 jump straight to their exact tab.

Right-click a row for the rest: open, mark as seen, favorite, or open the project folder.

Telling similar sessions apart

Parallel sessions often run in clones or worktrees of the same repository, which all have the same folder name. The overlay shortens each path to the drive plus the last two folders, like C:\…\work\app and D:\…\work\app, so two checkouts on different drives do not look identical. Sessions started by the desktop app show their title instead of a bare folder.

Background work folds under its parent

Claude Code can spin off background subagents, background shells and side sessions. Listing each of them as a separate row would bury the sessions you care about, so the overlay folds them under the session that started them, behind a small chip like ▸ 3. Click the chip to expand it when you want to see what is still running.

Keeping it out of the way

An always-on-top window has to earn its spot. The overlay hides itself when a fullscreen app such as a game or video is in front, collapses to just its header line from the right-click menu, minimizes to the tray, and remembers where you put it. It can start with Windows or at Mac login so the list is already there when you open your first session.

The result is a simple routine: start sessions, get on with something else, and glance at the corner of the screen (or wait for the chime) to know which one needs you next.
