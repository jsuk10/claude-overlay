What Claude Session Overlay reads on your computer (and what it never touches)

Updated: October 20, 2026

An app that watches your coding sessions should be clear about what it looks at. The short version: the overlay only reads local files that Claude Code and the Claude desktop app already write on your machine. It sends no network requests, has no account or telemetry, and never reads your login tokens or API keys. The source is MIT-licensed on GitHub, so every line below can be checked.

What it reads

InformationFile
Running sessions and their state (working, idle, waiting for input)~/.claude/sessions/<pid>.json
Model, context tokens, background tasks~/.claude/projects/<project>/<session>.jsonl
Context window size and auto-compact point~/.claude/cache/model-catalog/*.json and autoCompactWindow in ~/.claude/settings.json
Weekly and 5-hour usageplan-usage-history.json from the Claude desktop app
Session titles and split-view layoutThe desktop app's session files and claude_desktop_config.json

The desktop app's files live in %APPDATA%\Claude on Windows (or the matching folder under %LOCALAPPDATA%\Packages for the Microsoft Store version) and in ~/Library/Application Support/Claude/ on macOS.

How much of the transcript it looks at

Session transcripts contain your whole conversation, so this is the file people ask about most. The overlay reads them only to find usage numbers (how many tokens the last reply used) and the start and end of background tasks. It does not display, store or send your prompts or the model's replies anywhere. Everything it pulls out stays in memory while it runs.

What it writes

The overlay keeps its own small settings in ~/.claude/session-hud/: which sessions you have marked as seen, your favorites, window position, theme and language. On macOS it also writes status.json there for the widgets to read. Running --dump writes a diagnostic snapshot to dump.txt in the same folder, only when you ask for it.

It never modifies Claude Code's own files. The one exception is opt-in: if you tick the session-hud mod option in the Windows installer, it adds the mod folder to CLAUDE_CODE_PLUGIN_DIRS in your Claude Code settings, and removes it again when you uninstall.

Why no network

Everything the overlay shows already exists on disk, so there is nothing to fetch. Usage limits come from the sample the desktop app saves locally rather than from calling Anthropic's servers with your credentials. That design has a cost: if the desktop app is not installed, the overlay cannot show usage limits, and it tells you so instead of guessing. The benefit is that the overlay cannot leak your conversations or tokens, because it never opens a connection.

The optional mod

The session-hud mod runs inside Claude Code, so it sees what Claude Code passes to mods: the session's usage figures, cost and limit reset times. It writes those to a small file per session in ~/.claude/session-hud/ for the overlay to pick up. It does not send anything over the network either.

This website

The website you are reading is separate from the app. It uses Google Analytics and shows Google ads, which use cookies. The privacy policy covers what that means and how to opt out. None of that applies to the app itself.
